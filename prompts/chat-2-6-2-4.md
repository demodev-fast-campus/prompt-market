지금 Clerk를 한국어로 현지화하기 위해 해야 할 일 목록을 만들고, 패키지를 설치한 뒤 레이아웃에 `koKR` 로케일을 연결하겠습니다. 설치 후 바로 `app/[locale]/layout.tsx`를 수정해 `ClerkProvider`에 `localization`을 주입하겠습니다.

ClerkProvider에 koKR 로케일을 연결하겠습니다. `app/[locale]/layout.tsx`에서 `@clerk/localizations`의 `koKR`를 import하고 `ClerkProvider`의 `localization` prop에 전달하겠습니다.

type Props = {
  children: React.ReactNode;
  params: Promise<{ locale: string }>;

    locale: 'ko_KR',
    type: 'website',

        height: 630,
        alt: '프롬프트 마켓 OG 이미지',
      },
    ],
  },
};

export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }));
}

export default async function LocaleLayout({ children, params }: Props) {
  // Ensure that the incoming `locale` is valid
  const { locale } = await params;
  if (!routing.locales.includes(locale as any)) {
    notFound();
  }

  // Providing all messages to the client
  // side is the easiest way to get started
  const messages = await getMessages();

  return (
    <html lang={locale} suppressHydrationWarning>
      <head>
        <link
          rel="preconnect"
          href="https://vitals.vercel-analytics.com"
          crossOrigin="anonymous"
        />
        <link rel="dns-prefetch" href="https://vitals.vercel-analytics.com" />
        <link
          rel="preconnect"
          href="https://cdn.vercel-insights.com"
          crossOrigin="anonymous"
        />
        <link rel="dns-prefetch" href="https://cdn.vercel-insights.com" />
      </head>
      <body className={`font-sans ${GeistSans.variable} ${GeistMono.variable}`}>
        <ClerkProvider localization={koKR}>
          <ThemeProvider
            attribute="class"
            defaultTheme="system"
            enableSystem
            disableTransitionOnChange
          >
            <NextIntlClientProvider messages={messages}>
              <Suspense fallback={null}>{children}</Suspense>
              <Toaster />
              <Analytics />
            </NextIntlClientProvider>
          </ThemeProvider>
        </ClerkProvider>
      </body>
    </html>
  );
}

홈을 열어서 언어 전환 UI를 찾고, 한국어로 전환 후 Clerk 컴포넌트 텍스트가 한국어로 보이는지 확인하겠습니다. 이제 브라우저를 열고 페이지 스냅샷으로 버튼을 식별한 뒤 클릭해 검증할게요.

언어 전환 상태를 확인하고 버튼을 클릭하기 위해 페이지의 헤더 컴포넌트 구조와 전환 버튼의 역할을 파악하겠습니다. 곧바로 파일을 열어 확인할게요.

언어 전환 버튼을 클릭해 드롭다운을 연 다음, '한국어'를 선택하고 URL과 한국어 텍스트 노출을 확인하겠습니다.

언어 메뉴에서 ‘한국어’를 클릭해 URL 변경을 확인하고, 이어서 로그인 모달을 열어 Clerk UI가 한국어로 노출되는지 검증하겠습니다.

언어 메뉴를 다시 열고 '한국어'를 선택해 기본(ko) URL로 이동되는지 확인한 뒤, 로그인 모달을 열어 Clerk UI가 한국어로 표시되는지 검증하겠습니다.

언어 전환 동작을 정확히 확인하기 위해, 먼저 `app/api/set-locale/route.ts` 구현을 열어 로케일 쿠키 설정과 리다이렉트 로직을 점검하겠습니다.

언어 전환이 /en에서 한국어로 바뀌지 않는 문제를 재현했고, 전환 핸들러가 기본 로케일(ko)로 비접두 경로로 이동시키면서 쿠키 반영 타이밍 이슈로 다시 /en으로 유지되는 것으로 보입니다. 전환 시 명시적으로 '/ko' 경로로 이동하게 수정하고, 이후 Playwright로 다시 검증하겠습니다.

- 현재 URL: `/` (한국어 기본 경로)
- 헤더 텍스트: 한국어(예: `프롬프트`, `프롬프트 검색...`, `로그인`, `회원가입`)

- 영어 선택 시 `/en`으로 이동, Clerk는 `enUS`로 표시됨
